# Agent 任务评测

`tasks/suite-v1.json` 包含 12 个可复现任务，覆盖只读问答、单文件与多文件修改、测试、构建、大文件、跨目录检索、失败恢复和本地 MCP。每次运行都会把任务文件复制到系统临时目录，并使用隔离的 `.claudecode` 数据库；不会在当前仓库或应用用户数据中执行模型修改。

## 使用

先启动 Ollama 并确认目标模型已安装；如要比较两条本地执行环，还需先完成 `npm run vendor:install`。然后运行：

```bash
npm run eval:agent -- --model qwen2.5-coder:14b
```

默认分别运行 Host 本地环与 local-MCP 环，每个任务重复 3 次。常用选项：

- `--backend host|local-mcp|both`：选择执行环。
- `--repeat 1..5`：重复次数；默认 3。
- `--task E01`：只运行一个任务。
- `--allow-network`：允许 E07 在临时工作区安装依赖；默认跳过。
- `--keep-workspaces`：保留临时工作区以复核失败。
- `--out <目录>`：指定 JSON 与 Markdown 报告目录。
- `--dry-run`：仅验证并列出 12 项任务，不连接模型。

报告包含模型名/digest、Ollama 版本、执行环、任务与重复序号、断言结果、轮次、耗时、工具轨迹和编辑类工具失败数。`not_run` / `skipped` 不算通过；有 `manualReview` 的任务会标为 `needs_review`，须人工核对后再计分。

第一版只支持本地 Ollama，不调用云端 API，也不会复制云供应商密钥；子进程使用临时 HOME 和临时应用数据目录。E07 默认跳过，只有显式传 `--allow-network` 才会要求模型安装网络依赖。评测工作区与应用数据是隔离的，但操作系统层没有禁止任意出站网络，因此只应使用仓库内这份受审阅的任务集，不要把未知任务文件交给执行器。E12 只在 local-MCP 环运行，返回的模型标签仍需对照 `/api/tags`。当前环境若没有 Ollama 或未指定模型，只会输出 `not_run` 报告，不会猜测或伪报通过。

任务文件里的断言是预先登记的评分条件。修改任务定义后应提升 `version`，并为不同任务集版本分别解读结果；不能把一次模型生成的自然语言声明当作测试通过。
